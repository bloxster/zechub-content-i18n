What changed

Before

The live site depended on Google Translate for many localized reading flows. That meant page content could be sent through third-party runtime translation, and technical Zcash terms could be mistranslated.

Now

The pilot serves Italian content from a repository-controlled translation tree. English remains the source of truth and is used as fallback when an Italian page is not ready.

Delivered in the pilot

  • ✓ `next-intl` message boundary for English and Italian UI text.
  • ✓ Canonical English routes remain unprefixed, such as /wallets.
  • ✓ Italian routes use a locale prefix, such as /it/wallets.
  • ✓ /en/... redirects to canonical English routes.
  • ✓ Markdown lookup supports Italian translations with English fallback.
  • ✓ Google Translate scripts, widgets, cookies, and DOM translation behavior are removed from the pilot architecture.
  • ✓ Protected Zcash terminology is validated by script and GitHub Actions.

Pilot content

The first Italian translation set focuses on high-value wiki pages:

Wallets Shielded Pools ZK-SNARKs Arborist Calls

Italian Markdown lives under the mirrored path translations/it/site/.... This keeps translation work reviewable through normal pull requests instead of hidden in browser-side machine translation.

Protected terminology

Terms such as Zcash, ZEC, ZecHub, Orchard, Sapling, FROST, Unified Address, and wallet/project names are kept stable.

The content repository includes translation/protected-terms.json and scripts/check-protected-terms.mjs. The check fails when a protected term present in the English pilot source is missing from the Italian translation.

What remains before publication

  1. Italian-speaking editorial review of pilot translations and visible UI labels.
  2. Final build and navigation QA for English canonical routes and Italian routes.
  3. Upstream pull requests against the ZecHub application and content repositories.
  4. Clear public credit for related prior architecture work from ZecHub contributors.

Second stream: privacy hardening

Translation privacy is only the first layer. A separate privacy stream should address YouTube embeds, remote images and wallet icons, Google Maps, telemetry endpoints, AI assistant disclosure, wallet likes, and strict browser security headers.

That work should be scoped separately so the translation deliverable can ship cleanly without hiding a larger site-wide privacy audit inside the same milestone.
